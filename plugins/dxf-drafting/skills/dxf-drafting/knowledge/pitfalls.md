# Pitfalls (traps actually hit or well known). Format: trap → symptom → fix. Add new ones at the top.

1. **Hebrew SHX text stored as Latin characters** → inspector shows `j,l 3-3`; PNG shows gibberish/mirrored. Fix: `dxflib.decode` (Hebrew keyboard layout) to read, `dxflib.encode` to write, and only when the text style's font is an SHX Hebrew font (`Sivan`, `HEBTXT`, `MIRYL`). Never write real Unicode Hebrew into those styles; for TTF styles Unicode is right. Check the style first.
2. **Dimension extension lines invisible** → `dim_25` has `dimexo=40` (> offset). Fix: per-dimension override `dimexo=1.5, dimexe=2.0`.
3. **Dimension created but nothing drawn** → forgot `.render()`.
4. **Layer name has a space** (`5_HATAH _KONTUR`) → exact string match fails if copied loosely. Copy from `layers` output.
5. **Break-line zigzag in an outline** → gets measured as tiny steps. Filter narrow zigzag polylines (`is_break_mark` in `dim_section.py`) and apply a minimum step size. Still noisy on 5-5: see roadmap.
6. **Dim text overrides** (`text='65'` on an 85 dim) → stale numbers from edited geometry. `audit` flags them; never copy; ask.
7. **Duplicate entities** (stacked identical hatches/lines) → harmless visually, inflates quantities; `audit` reports; don't delete without asking.
8. **Anonymous blocks / dimension geometry** are regenerated by AutoCAD on edit; don't hand-edit `*D` blocks.
9. **Saving changes** → user's rule: update the ORIGINAL in place, but make `FILE.bak` first. (Superseded the old "never overwrite" rule, 2026-10-03.) If AutoCAD has the file open, the save may fail or be locked: ask to close it.
10. **Wrong section picked** — user digit swaps (`67-67` meant `76-76`). When a name isn't found, list the available titles and confirm.
11. **Heredoc with Hebrew/quotes in Git Bash** → "unexpected EOF". Use the Write tool for script files.
12. **`$INSUNITS` is not proof of units** — confirm by measuring a known element (a 20 cm wall measures 20 in a cm file).
13. **Scale confusion** — text/arrow/offset values are drawing units; at 1:25, 15 cm offset = 6 mm on paper. Match the file's own `dim_*` style (`dim_25` for 1:25, `dim_50` for 1:50, `dim_100_*`).

- Hebrew SHX notes copied from a reference must also copy the TEXT's `text_generation_flag` (mirrored = 2 for the 'Sivan' slab notes). Without it the text is not mirrored and runs the wrong way from the insert. Check `entity HANDLE` of a reference text before writing new ones.
- Nested anonymous blocks (`*U…`, from Divide/Measure with a block) hide dots: use `insert.virtual_entities()` recursively to read their positions.

- AutoCAD refreshes `FILE.bak` on EVERY user save, so a .bak is NOT a pristine baseline after the user has saved again. To undo your own earlier additions, record their signature (layers + the user's own entities, e.g. the user's help-line fragments) BEFORE editing, or keep your own timestamped copy; verify the removed count equals what you added (here 218 = 104 dots + 26 help + 26 lines/polys 57 + 36 leaders + 26 texts) before saving.
- Red revision clouds the user draws (layer `60_HATCH_ADAMA`, bulged LWPOLYLINE, ACI 1) mark where something is missing: find them by diffing against your last copy and rendering each bbox.

- Large project DXF (36 MB) loads in ~4 s but every `dxf_inspect png` reloads it: write one throwaway script that loads once. `ezdxf.bbox` needs `from ezdxf import bbox`. The user may switch files mid-task and re-save markup (clouds, white cells) after you looked: re-scan the named file before saying something is missing.

- **Locked / re-saved files**: a DXF open in AutoCAD is not writable (`Permission denied`, `cp: Device or resource busy`) and gets re-serialized on save (size changes, content the same). Test `open(f, 'ab')` before a batch and diff against the last snapshot before restoring anything, otherwise you may erase the user's edits.
- **Shell traps on Windows**: bash heredocs with quotes/backslashes broke repeatedly - write patch scripts to a file (Write tool) and run them; `$TEMP` in bash is not always the path Python/Read see (use the real `C:\Users\<user>\AppData\Local\Temp`); `sleep` loops are blocked, use background commands; a render of a 4 MB plan takes 1-2 min - batch renders in one background process.
- **A confident wrong model lasts only until the user sees it**: the solid-slab 1-1 was wrong because I never asked what the neighbouring slab was, while the plan already encoded it (span arrows). Look for the plan's own encoding of a fact before modelling it.
- **Silent drops**: a first batch that drew 24 types and ignored 34 labels was accepted by the tool and rejected by the user; always print coverage (inputs -> outputs) and list what is left.

- **ezdxf `get_measurement()` is 0 for some dims after the user's CAD save**: measure by projecting p1->p2 on the dim angle. Aligned dims have NO `angle` attribute (use atan2 of p1->p2); `dimtype & 7` = 0 linear, 1 aligned, 3/4 diameter / radius; bit 32 only means "user text position".
- **Upside-down dim text**: ezdxf renders aligned / rotated dim text along p1->p2 without flipping; direction in (90,270] = reversed text. Swap p1/p2 and negate the offset (done in `plan_elements.Out.aligned`); verify via the geometry block TEXT rotation.
- **Wall material ("is this text on a wall?")**: use the wall HATCH paths (layer `63_HATCH_KIR_OLE`, even-odd over all paths), not the 82_KIR_OLE outlines (the big ones enclose rooms).
- **Re-runnable recipes**: a recipe editing the user's plan must detect its own earlier output (coverage test, "chain already there") or a second run duplicates dims; test with `--dry` on the processed file and expect 0 changes.
- **Review renders**: zoom (PNG window of 1000-3000 units) before judging text / placement; whole-plan renders are unreadable.
- **Shell**: heredocs that nest quotes (python in bash) failed again - write a patch script with the Write tool and run it.
- **Several plans in one DXF**: find which plan a title belongs to by the TEXT insert (titles can sit far right of the plan, e.g. 'גלריה 1-' at x 97k beside a plan at x 76-86k, same y band); recipes written for one plan must be limited by box (monkey-patch the loader, drop site/parcel outline polygons >= 9000) and old output removed by box (`plan_gallery.clear_dims`, also delete the dim's anonymous block).
- **Before regenerating over earlier output**: diff the user's current file against the pre-run snapshot (`dxflib.diff`): only my dims + their cloud => safe to delete mine and re-run. Do NOT print the diff of a cloud polyline (thousands of vertices): print type counts.
- **Shell**: `ls $TEMP/glob*` fails in this bash (TEMP is a Windows short path); use `ls "$TEMP" | grep`. Render crops of 2000-2500 units; whole-plan PNGs are too small to read.
- **Beam edges are LINEs / 2-point polylines on 93_KORA**: a loader that only reads LWPOLYLINE misses part of them (query 'LWPOLYLINE LINE'). Columns' chain `v` is -x (uv convention): never mix real and uv coordinates for new chains (negated x dims).
- **A greedy cover loop needs a progress guard**: a face dropped by a jog filter never gets covered and re-adds the same chain forever (hundreds of junk dims); drop un-coverable faces explicitly.
- **Locked file**: the user may open the DXF in CAD (and paste new plans into it) between turns: a PermissionError on `open(file,'ab')` means DO NOT write a copy; say so and give the command.
- **Set cover for dim lines**: weighting by dims-per-face explodes the line count (short lines through empty areas); use max-new-coverage greedy + reverse-delete + extension-line reach. A line must not run within 3 of a parallel edge; door-jamb segments (20-25) need a candidate inside the wall thickness.

- **Windows console garbles Hebrew** (prints `?`): write analysis output to a UTF-8 file and Read it. `dxflib.decode` maps ALL ASCII incl. '/', '.', digits-adjacent punctuation: a Hebrew-style layer (451TEXT_KORA_100) also holds beam sizes '200/100' that decode would turn into '200.100': decode only texts containing lowercase letters (done in `plan_layers.py`).
- **ezdxf load of the 8 MB plan takes ~60 s**: one process per question; scripts that print thousands of lines (height filters on TEXT) overrun the 120 s tool timeout and are killed - filter first, run long scripts with `timeout` and read the output file. Unquoted `python - <<E` heredocs after a `cd` into a Hebrew-named folder work; the shell cwd resets each call, so use absolute paths.
- **Do not read a plan from a first render**: the whole-plan PNG misplaced rooms and scale; always verify from coordinates + a zoomed render (see knowledge/structural-plan-reading.md 'Mistakes').
- **Reading dims from a CAD-saved file**: `get_measurement()` can be 0; use defpoint2/defpoint3 (measured points), defpoint (line position), `text_midpoint` (actual text position, user shifts show here), and the anonymous `*D` block MTEXT for the rendered text. Heredoc python containing `\"` inside a bash `-c` string broke parsing twice: write scripts with the Write tool.
- **The user's example is the spec, but audit it too**: the example lines themselves omit some crossings (hidden lines, openings, outer walls); do not copy omissions silently - ask once.
- **Noise**: `plan_elements.Stripes/Out` iterates bbox.extents over INSERTs and prints thousands of 'copy process ignored ACDB_BLOCKREPRESENTATION_DATA' lines - filter with `grep -v 'copy process'` when reading recipe output. A plan_rows run on the 8 MB gallery file takes ~4 min: run in the background and wait with an until-loop on a 'finished' marker.
- **The box for a plan copy must include the perimeter wall** (gallery -1: y 36300..43200, perimeter bbox y 36455..43026); the old box y>=38000 missed the south ramp zone and the user's Y line start.
- **Jog tolerance**: faces closer than 12.5 are one face (wall 42966 vs slab edge 42956; beam 81636 vs pier 81641); audit crossings with --tol 12.5, strict 2 flags these as false misses.
- **PermissionError on save = the user has the DXF open in CAD again** (happened 2026-10-13 after 4 successful in-place runs): the run output is lost, nothing written; do not write a copy, tell the user to save + close, then re-run (re-runs are safe: `--replace-since` deletes only the previous output).
- **dxflib.backup keeps only the last 6 snapshots per tag**: the pre-run snapshot I used as 'before any output' was rotated out after 7 runs (FileNotFoundError on --replace-since). Fix: generated dims carry xdata CLAUDE_ROWS; `plan_rows.py --replace` removes exactly them; as fallback give TWO snapshots to --replace-since (intersection = the user's dims).
- **A patch by string slicing can match inside a longer line** (`'    for name...'` inside an 8-space line left stale code and an IndentationError): patch scripts must anchor on a full unique line, and run ast.parse + the tests before any run on the user's file.

- Marked example = one instance of a family: when the user clouds 3 X-marked openings, scan the WHOLE plan for the same block shape (there were 10). Entities of other types (INSERT bowtie blocks) are invisible to a LINE/LWPOLYLINE-only loader - check `query('INSERT')` for unseen symbols.
- **Polyline bulges (arcs) are invisible to `get_points('xy')`**: an outline / wall with arc segments was measured along its chords (chains 440-500 short of the curved wall, user's blue clouds 2026-10-14). Flatten with `ezdxf.path.make_path(e).flattening(d)` before any intersection, clipping or point-in-polygon.
- **plan_rows' 12.5 face merge keeps the first (inner) face**: the outer wall face within 12.5 is dropped, chains end 10 short of the outline; snap ends to the outline crossing (`plan_xlines_lf`).
- **An audit gap is not a licence to add lines**: after the user fixed the line positions (Xlines), the coverage audit showed unread faces and I added 18 lines - rejected. Report gaps; add only what the user marks.
- **Writing scripts with a bash heredoc**: a long Python body with quotes failed ('unexpected EOF') and a `cat > x.py` after `cd project` dropped the file INTO the project folder; use the Write tool with an absolute scratchpad path.
- **The user's own dims may carry my xdata tag** (a dim from an older run was tagged CLAUDE_ROWS): `--replace`-style deletion must key on a recipe-specific marker ('xline_dims'), never on the generic tag.
- **Rotated linear dim in ezdxf**: `add_linear_dim(base=<point on the line>, p1, p2, angle=deg, location=<text centre>)`; measured length = projection on the angle; extension lines are perpendicular to the dim line. Re-place a text later with `DimStyleOverride(dim).set_location(loc, leader=False, relative=False)` + `.render()`.
- **Never add lines the user did not mark - not even 'companion' lines**: for red clouds I first rebuilt the chain (sizes split 160.8 + 39.2), then switched to parallel companion lines to fix the readability: the user rejected the companion lines as extra dimensions ('only along the XLINEs I created'). When a rule of the user conflicts with readability, follow the rule and REPORT the cost. Also: test 'already dimensioned' by the extension points on THIS element, not by a matching length elsewhere.
- **`open(p,'w').write(f(s))` truncates the file BEFORE f runs**: an exception inside f (a regex template with `\D`) left recipes/INDEX.md empty (restored from the plugin cache copy + rows rebuilt from docstrings). Always compute the new text first (`new = f(s)`), then open for writing; never put `\` paths in `re.sub` replacement strings (use a function).

- ezdxf `DimStyleOverride(dim).render()` on an existing dim resets text_midpoint (all moved). To restyle (layer/dimstyle) and keep text: `o.set_location(old_text_midpoint, leader=False, relative=False)` first, then `render()`.

- ezdxf render of a dim with set_location splits the dimension line around the text when the text centre is too close (dim_50: 7 from line -> split; 10.7 -> whole). Count LINEs on the defpoint line inside the anonymous block after moving texts.

- Packaging for other PCs: embeddable Python needs `._pth` with `Lib\site-packages`, the app dir and `import site`; isolated mode means no script-dir on sys.path (scripts must insert their own paths). ## Moving an INSERT does not move its ATTRIB entities (2026-10-15)
`insert.dxf.insert = ...` leaves the attributes at their old WCS positions: the numbers of my moved/turned `hat` marks were left behind (user: "centre the text properly"). After moving/rotating/mirroring a block with attributes, re-place each `attrib` (local frame -> WCS: ins + R(rot)*(sx*lx*k, ly*k)); learn the offsets from a pair the user did by hand.

## The user's dots can be nested anonymous dynamic-block refs (2026-10-15)
`*Uxxx` INSERTs on layer `1922_ZIUN_DOT_T+I` wrap the plain block `dot barzel` (circle r1.25 + hatch) two levels deep (scale -0.896 / 0.896, rot 180). When reading a user detail, unwrap to the leaf block; when drawing, insert `dot barzel` directly with those scales on that layer (fallback: solid 2-pt polyline dot). A signature comparison (translate cell, round to 0.1, compare per entity key) is the way to prove a recipe reproduces a hand drawing.

## A control character hidden in a regex literal (2026-10-15)
`TAG2 = re.compile(r'...(\d+)')` had been saved with a real backspace (0x08) instead of backslash-b, so the pattern never matched and slanted-beam pairs were reported as "nothing". Symptom: a regex that "looks right" matches nothing; check with `od -c` / `ord()`. In patch scripts use raw strings and never write `` inside a normal string.

## Output file locked by the CAD program (2026-10-15)
`doc.saveas` raised PermissionError mid-task (file open in CAD, no side copy allowed): the snapshot is taken first, then stop and ask the user to save and close; re-read mtime and markers after they do (they save edits meanwhile).

## Text runs right-to-left from its insert (2026-10-15)
Hebrew title texts (mirrored style) extend LEFT of their insert and ezdxf's bbox counts the `%%U` codes: never centre them from the bbox. Calibrate on the user's hand-placed example (insert - centre = +26 at 9 high).
