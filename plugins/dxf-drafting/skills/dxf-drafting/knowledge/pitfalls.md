# Pitfalls (traps actually hit or well known). Format: trap → symptom → fix. Add new ones at the top.

1. **Hebrew SHX text stored as Latin characters** → inspector shows `j,l 3-3`; PNG shows gibberish/mirrored. Fix: `dxflib.decode` (Hebrew keyboard layout) to read, `dxflib.encode` to write, and only when the text style's font is an SHX Hebrew font (`Sivan`, `HEBTXT`, `MIRYL`). Never write real Unicode Hebrew into those styles; for TTF styles Unicode is right. Check the style first.
2. **Dimension extension lines invisible** → `dim_25` has `dimexo=40` (> offset). Fix: per-dimension override `dimexo=1.5, dimexe=2.0`.
3. **Dimension created but nothing drawn** → forgot `.render()`.
4. **Layer name has a space** (`5_HATAH _KONTUR`) → exact string match fails if copied loosely. Copy from `layers` output.
5. **Break-line zigzag in an outline** → gets measured as tiny steps. Filter narrow zigzag polylines (`is_break_mark` in `dim_section.py`) and apply a minimum step size. Still noisy on 5-5: see roadmap.
6. **Dim text overrides** (`text='65'` on an 85 dim) → stale numbers from edited geometry. `audit` flags them; never copy; ask.
7. **Duplicate entities** (stacked identical hatches/lines) → harmless visually, inflates quantities; `audit` reports; don't delete without asking.
8. **Anonymous blocks / dimension geometry** are regenerated by AutoCAD on edit; don't hand-edit `*D` blocks.
9. **Saving changes** → user's rule: update the ORIGINAL in place, but make `FILE.bak` first. (Superseded the old "never overwrite" rule, 2026-10-03.) If AutoCAD has the file open, the save may fail or be locked: ask to close it.
10. **Wrong section picked** — user digit swaps (`67-67` meant `76-76`). When a name isn't found, list the available titles and confirm.
11. **Heredoc with Hebrew/quotes in Git Bash** → "unexpected EOF". Use the Write tool for script files.
12. **`$INSUNITS` is not proof of units** — confirm by measuring a known element (a 20 cm wall measures 20 in a cm file).
13. **Scale confusion** — text/arrow/offset values are drawing units; at 1:25, 15 cm offset = 6 mm on paper. Match the file's own `dim_*` style (`dim_25` for 1:25, `dim_50` for 1:50, `dim_100_*`).

- Hebrew SHX notes copied from a reference must also copy the TEXT's `text_generation_flag` (mirrored = 2 for the 'Sivan' slab notes). Without it the text is not mirrored and runs the wrong way from the insert. Check `entity HANDLE` of a reference text before writing new ones.
- Nested anonymous blocks (`*U…`, from Divide/Measure with a block) hide dots: use `insert.virtual_entities()` recursively to read their positions.

- AutoCAD refreshes `FILE.bak` on EVERY user save, so a .bak is NOT a pristine baseline after the user has saved again. To undo your own earlier additions, record their signature (layers + the user's own entities, e.g. the user's help-line fragments) BEFORE editing, or keep your own timestamped copy; verify the removed count equals what you added (here 218 = 104 dots + 26 help + 26 lines/polys 57 + 36 leaders + 26 texts) before saving.
- Red revision clouds the user draws (layer `60_HATCH_ADAMA`, bulged LWPOLYLINE, ACI 1) mark where something is missing: find them by diffing against your last copy and rendering each bbox.

- Large project DXF (36 MB) loads in ~4 s but every `dxf_inspect png` reloads it: write one throwaway script that loads once. `ezdxf.bbox` needs `from ezdxf import bbox`. The user may switch files mid-task and re-save markup (clouds, white cells) after you looked: re-scan the named file before saying something is missing.

- **Locked / re-saved files**: a DXF open in AutoCAD is not writable (`Permission denied`, `cp: Device or resource busy`) and gets re-serialized on save (size changes, content the same). Test `open(f, 'ab')` before a batch and diff against the last snapshot before restoring anything, otherwise you may erase the user's edits.
- **Shell traps on Windows**: bash heredocs with quotes/backslashes broke repeatedly - write patch scripts to a file (Write tool) and run them; `$TEMP` in bash is not always the path Python/Read see (use the real `C:\Users\<user>\AppData\Local\Temp`); `sleep` loops are blocked, use background commands; a render of a 4 MB plan takes 1-2 min - batch renders in one background process.
- **A confident wrong model lasts only until the user sees it**: the solid-slab 1-1 was wrong because I never asked what the neighbouring slab was, while the plan already encoded it (span arrows). Look for the plan's own encoding of a fact before modelling it.
- **Silent drops**: a first batch that drew 24 types and ignored 34 labels was accepted by the tool and rejected by the user; always print coverage (inputs -> outputs) and list what is left.

- **ezdxf `get_measurement()` is 0 for some dims after the user's CAD save**: measure by projecting p1->p2 on the dim angle. Aligned dims have NO `angle` attribute (use atan2 of p1->p2); `dimtype & 7` = 0 linear, 1 aligned, 3/4 diameter / radius; bit 32 only means "user text position".
- **Upside-down dim text**: ezdxf renders aligned / rotated dim text along p1->p2 without flipping; direction in (90,270] = reversed text. Swap p1/p2 and negate the offset (done in `plan_elements.Out.aligned`); verify via the geometry block TEXT rotation.
- **Wall material ("is this text on a wall?")**: use the wall HATCH paths (layer `63_HATCH_KIR_OLE`, even-odd over all paths), not the 82_KIR_OLE outlines (the big ones enclose rooms).
- **Re-runnable recipes**: a recipe editing the user's plan must detect its own earlier output (coverage test, "chain already there") or a second run duplicates dims; test with `--dry` on the processed file and expect 0 changes.
- **Review renders**: zoom (PNG window of 1000-3000 units) before judging text / placement; whole-plan renders are unreadable.
- **Shell**: heredocs that nest quotes (python in bash) failed again - write a patch script with the Write tool and run it.
- **Several plans in one DXF**: find which plan a title belongs to by the TEXT insert (titles can sit far right of the plan, e.g. 'גלריה 1-' at x 97k beside a plan at x 76-86k, same y band); recipes written for one plan must be limited by box (monkey-patch the loader, drop site/parcel outline polygons >= 9000) and old output removed by box (`plan_gallery.clear_dims`, also delete the dim's anonymous block).
- **Before regenerating over earlier output**: diff the user's current file against the pre-run snapshot (`dxflib.diff`): only my dims + their cloud => safe to delete mine and re-run. Do NOT print the diff of a cloud polyline (thousands of vertices): print type counts.
- **Shell**: `ls $TEMP/glob*` fails in this bash (TEMP is a Windows short path); use `ls "$TEMP" | grep`. Render crops of 2000-2500 units; whole-plan PNGs are too small to read.
