# Pitfalls: traps actually hit (trap -> symptom -> fix), grouped by theme and de-duplicated 2026-10-23. Add new ones to the right group, merge a repeat into the existing entry instead of adding another.

## A. Hebrew and text
- **Hebrew SHX text stored as Latin characters** (`j,l 3-3`): decode with `dxflib.decode` (Hebrew keyboard layout), write with `encode`, ONLY when the text style is an SHX Hebrew font (`SIVAN`, `HEBTXT`, `MIRYL`, `HEBREW_NEW`); TTF styles take Unicode. Check the style first. PNG renders show SHX Hebrew mirrored / gibberish - that is the renderer, measure with `scripts/shx_width.py`.
- Copy the reference text's `text_generation_flag` (2 = mirrored) with its text; mirrored (RTL) texts and `%%U` titles extend LEFT of the insert point and ezdxf's bbox is wrong for them: never centre from the bbox, calibrate on the user's hand example (title insert - centre = +26 at 9 high).
- Plan texts are stored REVERSED, digits included (`08=D` = D=80); `decode` maps ALL ASCII incl. `/` and `.` (a beam tag `200/100` would become `200.100`): decode only texts with lowercase letters. A parser that silently returns None (level regexes) turns a whole feature into a no-op: print how many values it found and compare with the raw attribs of 2-3 elements.
- Windows console garbles Hebrew (`?`): write analysis output to a UTF-8 file and Read it.
- Slab thickness lives in TWO places: `D=nn` TEXT and the `S_M` level-marker block ATTRIBS (found by `slab_markers`); search both before concluding 'no thickness'.

## B. Files, saving, locks, snapshots
- User rule: edit the CURRENT file in place after a timestamped snapshot, never create a side file. A DXF open in CAD raises PermissionError on save (test `open(f, 'ab')` before a batch; a `.dwl` next to it = open): nothing was written - say so, ask him to save + close, re-run the SAME script on the original (re-runs are safe). Write a side copy only if HE tells you to (once done for sections_ramla_obround.dxf); never copy a side file over the original (he may have saved meanwhile).
- AutoCAD refreshes `FILE.bak` on EVERY save: a .bak is not a pristine baseline. `dxflib.backup` keeps only the last 6 snapshots per tag (rotated out after 7 runs). To undo my own additions record their signature (xdata tag, layers) BEFORE editing; verify the removed count equals what was added.
- Before regenerating over earlier output, diff the user's current file against the pre-run snapshot (`dxflib.diff`; print type counts, not the thousands of vertices of a cloud polyline): only my entities + his cloud -> safe to delete mine and re-run. Never restore a snapshot over the file without checking that its mtime still equals my last write.
- To learn from HIS hand edits snapshot my own output right after every write (`FILE.mine-<tag>`); a diff against the pre-write `.bak-<tag>` mixes his edits with my moves.
- He re-saves mid-turn and may paste whole other plans into the file or name another file: re-read mtime + markup before every write, limit work with `--box`, check extents.
- A saved file identical to my last output = he only re-saved: look for what I still owe (unnumbered marks, UNVERIFIED items) instead of asking.

## C. Windows shell and scripting
- Git-bash heredocs with quotes / Hebrew / backslashes fail ('unexpected EOF'); a `cat > x.py` after `cd project` drops the file INTO the project; `$TEMP` in bash is not the path Python / Read see. Write scripts with the Write tool to an absolute scratchpad path (UTF-8, `encoding='utf-8'` when opening Hebrew paths), run them from a file, use absolute paths (cwd resets each call). Never `python -` / `python -I -` / a REPL in a tool call (hangs on stdin). No `sleep` loops (use background commands + an until-loop on a 'finished' marker).
- **Patch scripts**: anchor on a full unique line and run `ast.parse` + the tests before any run on the user's file; a slice can match inside a longer line (IndentationError). In a normal string `\b` is a backspace and `\d` a double backslash (a regex silently never matched; a real 0x08 hid in a regex literal) - use raw strings, check with `ord()`. A trailing `# comment` on a one-line `a = ...; b = ...` swallows the rest. `open(p,'w').write(f(s))` truncates BEFORE f runs (an exception emptied recipes/INDEX.md): compute `new = f(s)` first, never put paths in `re.sub` replacement strings. Default to `--dry` (chaining `python patch.py` without it WROTE the file); a one-off script that appends to skill files must run ONCE.
- PowerShell 5.1: `Set-Content -Encoding UTF8` writes a BOM (breaks python source and `json.load`: use `[IO.File]::WriteAllText(..., New-Object Text.UTF8Encoding($false))` or json `utf-8-sig`); `&&` is invalid; hashtable keys are case-insensitive (`Dl` vs `dl`) - build JSON specs in Python; Hebrew paths in python source need UTF-8 without BOM.
- **accoreconsole + git-bash**: MSYS rewrites the `/i` `/s` switches, the console starts but never runs the script (hangs, no error). Launch from PowerShell or Python subprocess with short ASCII paths (C:\arrtest). ARRAYRECT 2024: `_COL n TOTAL`, `_R rows BETWEEN elev`; the array INSERT takes the current layer (set CLAYER); the source object is consumed (delete the other dots first). DXFOUT of a DXF keeps AC1032 and every other entity. A `SAVEAS` script hung 300 s.
- Subprocess output of child recipes: decode with `errors='replace'`; children run with `python -I`, so a recipe must add its own dir to `sys.path`.

## D. DXF / ezdxf API traps
- Dimensions: `.render()` is REQUIRED (no geometry block otherwise); the style `dim_25` has `dimexo=40` -> override `dimexo=1.5, dimexe=2.0`; never copy `text='65'` overrides (stale numbers, `audit` flags them); `get_measurement()` can be 0 after a CAD save - project p1->p2 on the dim angle (aligned dims have NO `angle`: atan2 of p1->p2; `dimtype & 7` 0 linear, 1 aligned, 3/4 diameter / radius); read a saved dim from `defpoint2/3` (measured points), `defpoint` (line), `text_midpoint` (his text shifts), and the anonymous `*D` block. Delete a dim's anonymous block with it; don't hand-edit `*D` blocks.
- `add_linear_dim(location=...)`: `location` is the exact text midpoint; without it the text sits 18 from the line (23 for items narrower than the text); with p1 ABOVE p2 the text lands on the wrong side of a vertical dim - give the lower point first. Rotated dims: ezdxf-cookbook.md. `DimStyleOverride(dim).render()` on an existing dim RESETS the text midpoint: `set_location(old_mid, leader=False, relative=False)` first. A text centre too close to the line SPLITS the dim line around the text (dim_50: 7 -> split, 10.7 -> whole): after moving texts count the LINEs on the defpoint line inside the block.
- Upside-down aligned / rotated text: ezdxf does not flip; direction in (90, 270] = reversed -> swap p1 / p2 and negate the offset; verify via the geometry block TEXT rotation.
- Layer names may contain spaces (`5_HATAH _KONTUR`): copy exactly from `layers`. A layer a recipe creates itself gets colour 7: set the office colour (layers table in office-standards.md) and check after the first write.
- `$INSUNITS` is not proof of units (measure a known element); text / arrow / offset values are DRAWING units (1:25, 15 cm = 6 mm paper).
- **Bulges**: `get_points('xy')` ignores arcs - flatten with `ezdxf.path.make_path(e).flattening(0.4)` before intersection, clipping or point-in-polygon.
- **INSERT**: moving / rotating an INSERT leaves its ATTRIBs at the old WCS positions - re-place each attrib (local -> WCS: ins + R(rot)*(sx*lx*k, ly*k)), learn the offsets from a pair he did by hand. Nested anonymous blocks (`*U..`, Divide / Measure / dynamic blocks / arrays) hide dots: read with `virtual_entities()` recursively; the user's dots are two levels of `*U` around the plain block `dot barzel`; INSERT bbox via `ezdxf.bbox.extents` (the insert point can be far away). Dots may be associative array INSERTs: explode only what changes, re-run `bar_arrays.py` afterwards. Orphan array bodies after deleting a section are harmless.
- Blocks with 'copy process ignored ACDB_BLOCKREPRESENTATION_DATA' flood the console: filter with `grep -v 'copy process'`.
- `from ezdxf import bbox`; `bbox.extents` on TEXT is approximate (SHX metrics unknown).

## E. Reading the user (the expensive traps)
- **A confident wrong model lasts only until he sees it**: look for the plan's own encoding of a fact (span arrows, S_M markers, a `D=nn` without `+`) before modelling; my solid-slab 1-1 was wrong because I never asked what the neighbouring slab was. His own drawing is right until proven otherwise: derive the principle from what it encodes.
- **Silent drops**: always print coverage (inputs -> outputs, hat pairs / 2 vs numbered, labels -> beams -> sections) and list what is left; a first batch drew 24 types and ignored 34 labels.
- A marked example is ONE instance of a family: scan the WHOLE plan for the same shape (he clouded 3 X-marked openings, there were 10; entities of other types - INSERT bowties - are invisible to a LINE/LWPOLYLINE-only loader). The example is the spec but AUDIT it too: it omits some crossings; do not copy omissions silently - ask once.
- 'Only these' / 'otherwise as they are' limits a change to the clouded entities (list them first, touch nothing else); rule 4 'a correction is a rule for the family' applies to a mistake pattern, not to a spec he limited. Ambiguous nouns: read the newest cloud and name what it encloses before acting (I once scaled 122 cut marks when he meant the obround openings; undone by the inverse factor, not a snapshot restore, to keep his edits).
- Clouds (rules for reading them: conventions/markup-vocabulary.md): an EMPTY-looking cloud may enclose a pasted picture (OLE2FRAME, bbox inf): extract the group-310 hex chunks of the entity from the raw DXF -> compound file (`ÐÏà`) -> `olefile` stream CONTENTS = BMP (prepend a 'BM' header if it is a bare DIB) -> view it. Never skip an 'empty' cloud. Old revision-cloud layers (`60_HATCH_ADAMA`, `SHINUIM-TIKUNIM`) are ignored since the `claude` layer agreement.
- Section names: a digit swap (`67-67` meant `76-76`); when a name is not found, list the titles and confirm. He may switch files mid-task and re-save markup after you looked: re-scan the named file before saying something is missing.
- Do not read a plan from a first render (rooms and scale were misplaced; tanks are NORTH): verify from coordinates + a zoomed render; list every claim as verified or UNVERIFIED.
- Learning from his edit: diff against MY last snapshot with arrays virtually exploded (INSERT `*U` -> `virtual_entities`, nested), dots as centre sets, everything else by (type, layer, rounded geometry), ignore re-save noise (dim angle None vs 0); (copy-first method: conventions/markup-vocabulary.md) his clouds can be stale relative to my last patch - check the current geometry before deciding a cloud is 'not done'.

## F. Generators and recipes - hygiene
- **A silent `except Exception: pass` hides a feature that never worked** (2026-10-24: the hoop-note centring in general_beam fell back to the left in EVERY section because `shx_width` had no style `HEBTXT`; nobody noticed until the user centred it by hand). A fallback prints a WARNING; a new text style needs an entry in `shx_width.FILES`; after adding a 'centre / fit' rule, MEASURE the generated output (centre of the text vs centre of what it labels), do not trust that the code path ran.
- **Never use a fixed scratch file name** (`sp_extent.dxf` in %TEMP%, 2026-10-24): two runs at once (the user's app run + my test run) overwrote it, the draw step read a half-written file (`missing ENDSEC`), NO section was drawn and the app still said 'done'. Use `tempfile.mkdtemp()` per call and delete it; never run tests / pipelines on this machine while the user may be running the app. A crashed draw step must stop the round (sections_round exits with an ERROR), never continue to the finish passes.
- **Re-runnable**: a recipe must detect its own earlier output (coverage test, xdata tag) - run it TWICE, the second run must change nothing (`--dry` on the processed file = 0 changes). Tag with a recipe-specific marker (`xline_dims`), never the generic tag (his own dims may carry it). When cloning a template entity compute the offset from the TEMPLATE position, not a moving loop cursor (all clones stacked on one spot).
- After `--replace` any entity type the cleaner does not know survives as a ghost (INSERT dots of another recipe, LEADERs, `dot barzel`, `MH`): add every new entity type to `clear_cell` in the same edit and run `cell_dupes.py` + count the dots in a render.
- Before adding a 'convenient' fallback that fills a missing number (a plan-wide `D=80` note, a D=25 template), grep conventions / memory for 'default' / 'never guess': it re-breaks a rule he already taught. A template default is not evidence.
- A greedy cover loop needs a progress guard (a face dropped by a jog filter never gets covered and re-adds the same chain forever); drop un-coverable faces explicitly. Set cover: max-new-coverage greedy + reverse-delete + extension reach (weighting by dims-per-face explodes the line count); a line must not run within 3 of a parallel edge.
- 'Dry' runs must be dry: `sections_round.py --dry` re-orients and SAVES (snapshot `.bak-star-orient-*`). Verify COVERAGE at the end of every round. Keep the render/verification independent of the generator's own log (reopen the saved file).

## F2. Speed (a section round on a 9 MB plan: 280 s -> 118 s, identical output, 2026-10-24)
- **Profile first**: wrap `subprocess.run` and time every step (a 10-line harness, see CHANGELOG 2026-10-24). A 10-30 MB DXF costs ~1.3 s to read and ~1 s to save; the cost of a round is the NUMBER of reads / saves, not the drawing.
- **One load, one save for a batch of sections**: recipes' `main(argv, doc)` draw into an open document (`star_plan.execute` does this); a failing section is rolled back (new handles deleted) and redrawn as its own process. Never write a loop that starts one process per section.
- **Measure on a stand-in**: `star_plan.extent_base` = the plan reduced to its TEXTs + tables (no other entity, no `*D` / `*U` / `*E` blocks); extents equal the full plan's (tested). New entities are found by `$HANDSEED`, not by listing every handle.
- **No per-recipe re-open to audit** inside a batch (`DIMPLAN_FAST=1`, `dxflib.audit_saved`); the round re-opens and audits the final file once.
- **Render only the view**: `dxflib.render_png` draws entities whose bbox touches the box (`filter_func`) and fixes the figure shape itself (ezdxf resizes the figure to what it drew: set it back before `savefig`); a comment placed before `; fig.savefig(...)` on the same line silently skipped the save once.
- **bbox once**: `ezdxf.bbox.extents` per entity is the slow part of any scan; collect candidates once per run (`fit_rows.candidates`), do not rescan the whole plan per row.
- **App start**: the access check (Google Apps Script, 3-13 s, sometimes > 8) was 90% of the launch time; it now runs while the server starts and a timeout is retried once. Each call counts as a launch in the Sheet: never hedge / duplicate it, and never test it in a loop.

## G. Plan dimensioning traps
- **Never add lines he did not mark - not even 'companion' lines, not to fill an audit gap** (rejected: 18 ILP lines, 70-offset companions): report gaps and the readability cost. Test 'already dimensioned' by the extension points on THIS element, not a matching length elsewhere.
- Faces closer than 12.5 are one face (jog tolerance; audit crossings with `--tol 12.5`); `plan_rows.line_faces` keeps the INNER face, so chains ended 10 short of the outline: snap the ends to the outline crossing (`plan_xlines_lf`).
- Wall material = the wall HATCH paths (`63_HATCH_KIR_OLE`, even-odd over all paths), not the `82_KIR_OLE` outlines (the big ones enclose rooms). Beam edges are LINEs / 2-point polylines on `93_KORA` (query 'LWPOLYLINE LINE'); the pier-chain `v` coordinate is -x (uv convention) - never mix real and uv coordinates.
- Several plans in one DXF: titles can sit far right of their plan; limit by box (the box must include the perimeter wall: gallery -1 y 36300..43200), drop site / parcel outline polygons >= 9000, remove old output by box (also the dim's anonymous block). List every `9_KONTUR` contour > 5000 wide first.
- `plan_overlaps.py` treats every non-0 angle as Y: bogus hits on rotated dims (use `plan_repair.py`). A plan_rows run on the 8 MB gallery takes ~4 min (background + wait).

## H. Section drawing traps
- **Frozen layers hide a whole section round, and CLAYER on a frozen layer fails silently** (netivot 2026-10-24): the plan came with 54_HATAH_TEXT / 57_HATAH_ZIUN / 53_HATAH_MIDA frozen; titles, bars and dims were invisible and the ARRAYRECT results landed on the previously current layer (claude_Kontur, the user's channel). Fix: section_visibility.py (gate in sections_round + the app) and ar_arrays thaws the layer in its .scr (-LAYER T/ON/U) and logs CLAYER ok (a failed CLAYER aborts). Always check layer states (dxf_inspect layers) on a new plan and render with them.
- A cut crossing a wall / beam: classify by LAYER first (93_KORA beam, 8_KIR wall, 9_KONTUR edge); the `b/h` tag printed beside a strip often belongs to the crossing beam. Wrong-pairing and `--max-y` traps: sections-workflow.md section 2.
- `star_plan --draw` renumbers the marks even when a recipe subprocess failed (check the titles exist). `--cells-at` does not check for free space. A section taller than its row must be shifted into the frame; a recipe `--box` overlapping another section's overflow clears it (keep new frames clear of tall rows).
- Absolute y levels do not survive `align_row` / centring (every section is translated by its own dy): use relative positions (column dot order, KONTUR faces) and recompute levels from the file; `redraw_general.py` reads the origin from the beam-bottom line, so a `dx` nudge ACCUMULATES per re-run. After finishing passes check every frame's margins, not only the render.
- Colour work: change the LAYER colour, not entity overrides, when he says 'organize the layer colours'; diff the layer table + entity colours against my snapshot to read his intent.
- Sheet details that look 'wrong' versus the true view (slab side of a free edge) may be deliberate: he draws edge details in one orientation; do not mirror unless he asks.
- Moving a leader note: text + shelf + EVERY fork end together; the joint is whichever polyline end touches the LINEs (not always p[0]); exclude the note's own forks from the obstacle list (else a spurious conflict); assert contact before saving. Rotated (90) labels give false 'overlaps' in box checks. Attach each text to ONE shelf.
- Break-line zigzags in an outline are measured as tiny steps (`is_break_mark` + minimum step in `dim_section.py`).
- Heavy renders (19 MB file, minutes): write a montage script (XREF block lines + host entities, arrays exploded) instead of `dxf_inspect png`; render crops of 1000-3000 units, whole-plan PNGs are unreadable; batch renders in one background process; a 36 MB project loads in ~4 s but every `png` reloads it - write one throwaway script that loads once; scripts that print thousands of lines overrun the 120 s tool timeout (filter first, write to a file).

## H2. Added by the 2026-10-25 pre-release audit (each one hid a feature that did not work)
- **Name patterns die silently**: the three XREF recipes after the overlay matched `Sec (\d+)-(\d+)$` only, so on `...Sec0-8` they did 'nothing' and still reported success ('0 bars extended'). One reader per fact: `dxflib.xref_section_number`; a step that finds 0 sections must say so.
- **`python -I` (isolated) puts no script folder on `sys.path`**: a recipe that imports a sibling (`text_overlap`) works by hand and fails inside the round; add `sys.path.insert(0, <its own folder>)`.
- **`{x:g}` keeps 6 digits**: the planner hands a cell to a recipe as `-13752.2 / 268619`, the exact float differs by up to 0.5; code that recomputes coordinates (shutter, slope) must round the same way or its look-ups miss by 0.3.
- **Raw plan text is keyboard-layout text**: `45_TEXT_KORA` stores a b/h tag as `220.70` ('/' typed on the Hebrew layout), `451TEXT_KORA_100` as `220/70`; match raw with `[/.]`, never decode digits.
- **bbox of an array / anonymous block INSERT (`*U..`, `1BARS`) is meaningless** (geometry in absolute coordinates, extents reach (0,0)); measure a stamped template from non-INSERT entities + the insert points.
- **Sidecars for passes that need later state**: the slope label copies a mirrored SIVAN note that exists only after `sivan_text`, so `star_plan --draw` writes `FILE.slopes.json` and `sections_round` runs `slope_label --json` afterwards.
- **A planner marker is not a recipe option**: `--slope` / `--rshutter` are part of the group key (so different sections never merge) and are STRIPPED before a recipe sees the args (`split_slope`, `split_shutter`, `clean_args`).
- **A stale 'not drawn' note outlives its recipe** (the shutter said 'no taught recipe' for a day after `beam_shutter` existed): grep the planner notes when a recipe is added.
- **A radius is not an owner**: one shutter text within 450 of two cuts was drawn twice; assign each text to its NEAREST cut.
- **A dot that is not a polyline is never arrayed**: `bar_arrays` took only closed 2-vertex polylines, so the roller-shutter column and the slab-step rows (his `dot barzel` blocks) stayed loose in every round although 'reinforcement is ALWAYS an array'. Count loose `dot barzel` on the rebar layer after a round (0 expected); `bar_arrays` now accepts the block dots.
- **His example is one view**: the stamped 16-16 has the thick slab on the left because it was drawn looking E; the round flips pairs to view W, so the same pair shows it on the right - decide the side from the plan geometry and the view, never copy the example's side.

## H3. Added 2026-10-25 (netivot 9-9, bound XREF files, reference library)
- **Recipes run under `python -I` in `sections_round`**: the script folder is NOT on `sys.path`. Every recipe that imports a sibling (`plan_xlines_lf`, `bar_arrays`) must insert its own folder; a new recipe that crashes there is silent (the round prints one line) - test it with `python -I` (tests/run_tests.py has the case). Two new steps (indicator layer, array arrows) did nothing for a day because of this.
- **A pass that moves part of a detail leaves the rest behind**: `fit_rows` assigns entities to cells by BBOX CENTRE, so a detail straddling a divider is split (polyline moved, dim + note stayed). Tag such details as ONE object (XDATA `DXFSKILL_GROUP`, helper in `fit_rows.content`) and trace the passes: wrap `sections_round.run` to print the entity positions after every step (scratchpad `trace.py` pattern) instead of guessing which pass did it.
- **Explicit dimension text positions**: ezdxf `add_linear_dim(location=...)` fixes the text side; relying on the style's guess put the `64` text on the same side as the note and a later pass pushed both away.
- **Bound XREF files** (Bind -> DXF): fine; layers carry `$0$`, blocks stay named. The failures were plan-block names with a space (`Structural Plan - Level 01 GD`) and ONE unreadable section killing the whole scan (isolate per section).
- **A reference DXF can have EMPTY XREF blocks** (his 3841-CON_claude_): take the outlines from the file that has them (`ref_library.py build REF ORIG`). `dxf_inspect png` does not draw XREF block content; use a composite render (block lines translated by the insert + his entities) to compare.
- **Do not name a scratch script `types.py`** (shadows the stdlib, ezdxf import fails). Anonymous nested blocks of an XREF may be missing: iterate the block's entities and translate instead of `virtual_entities()`.
- **Version drift in installers**: `setup.ps1` / `portable_run.ps1` had a hard-coded version, the portable exe kept running the old unpacked folder; `build.py` now stamps the version from `app/server.py`.

## I. Packaging for other PCs
Embeddable Python needs a `._pth` with `Lib\site-packages`, the app dir and `import site`; isolated mode means no script-dir on `sys.path` (scripts insert their own paths: recipes are relocatable, no `~/.claude` paths). An IExpress exe returns immediately (installs async) and runs AppLaunched, not /Q commands: call `powershell -File setup.ps1` explicitly. The app copies `recipes/ scripts/ profiles/ assets/` flat from this skill.
