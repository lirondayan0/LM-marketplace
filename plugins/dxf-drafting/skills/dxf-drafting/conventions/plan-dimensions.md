## 1. Principles (the user's words, valid everywhere)
1. **Fewest dimensions, every element's sizes readable, as many CONTINUOUS lines as possible, nothing measured twice**, text never upside-down or on a wall, neat and precise. Face to face, never axes.
2. **X and Y only** (linear 0 / 90) - skewed elements get X + Y chains over their vertices. ONE exception: a TILTED Xline gets an ALIGNED chain along it (he marked the direction).
3. **ONLY on his marks**: the lines are his Xlines (mode A) or the generator's computed minimum (mode B). An audit gap is REPORTED, never filled with lines he did not mark (rejected twice: the 18 extra ILP lines, the 'companion' lines). When readability conflicts with this rule, follow the rule and report the cost.
4. **Continuous**: each line runs from one end of the plan to the other (perimeter to perimeter / boundary to boundary), items face to face, no gaps or overlaps.
5. **One side**: a line states the elements of ONE side only (extension lines reach one side), placed just outside the row it serves, so it is clear which element it belongs to.
6. **Every crossing is an item**: every element the line crosses (walls, piers, beams, slab edge, hidden items) is dimensioned by it; faces closer than 12.5 are one face; a contour line splitting an element splits its item (31 + 28) - kept.
7. **Reach limit = 1 m** (`plan_rows.EXT_MAX = 100`, env `DIM_REACH`; user 2026-10-14, supersedes 250 / 200 / 300): an element is picked up only if crossed or its nearest face is within 100 of the line; farther ones are reported, never added. Explicit cloud additions (`plan_clouds.py --reach 600`) keep their own reach.
8. **Measured once**: same two faces twice = delete one (value within 0.6 %). Old user dims are removed only when clouded or exact duplicates. Identical grid intervals repeated on several rows may be kept once (UNVERIFIED preference vs continuity).
9. No diameter dims on circles; no dim shorter than ~12.5 (jog faces < 12.5 count as read); `6_HATCH` marks (double-height spaces, opening symbols) are INFORMATIONAL: never dimensioned.
10. Text upright (aligned dim direction p1->p2 in (-90, 90]; swap the points and negate the offset otherwise).
11. Everything inside the plan boundary: nothing (dim lines, extension lines, texts) may leave it; elements outside are not dimensioned. Free items just outside a slab contour ARE elements of the plan when they lie inside the boundary.

## 2. Mode A - the mark-driven round (canonical workflow, user's own summary 2026-10-14)
You receive a plan with: (1) `claude_Kontur` = the closed boundary of the work (several regions possible); (2) `claude_DIM` XLINEs = where the lines go (horizontal -> X chain, vertical -> Y chain, tilted -> aligned chain); (3) a cloud on `claude_DIM` OUTSIDE the plan enclosing a SAMPLE DIMENSION: its LAYER and DIM STYLE are the ones every created dimension uses (the cloud's own layer is NOT the output layer; read by `plan_xlines_lf.dim_template`: clouds on `claude_DIM` first, then `claude`; clouds inside the plan skipped; a dim matches when 2 of its 3 points or its text midpoint lie in the cloud; frames around line + text only are accepted; no sample -> `36_MIDA_CLALI` / `dim_100`); (4) other clouds on `claude` = corrections (colours: markup-vocabulary.md).
**Run**: `python recipes/plan_round.py FILE --scan` (what marks exist, region count) -> same without `--scan` (dry round in a temp dir: plan_xlines -> plan_clouds -> plan_repair, then VERIFY: every dim point inside the boundary, text collisions, chain-end gaps, split lines) -> `--write` (snapshot + mtime check, saves, and **deletes the `claude_DIM` Xlines** - user 2026-10-14, no approval wait). The file may be open in CAD (PermissionError): ask him to save + close, never write a side copy.
Rules of the chains:
1. **Boundary** = `claude_Kontur` (`plan_xlines_lf.kontur_analyze` tolerates closed flag, start=end, overshoot / tail, pieces joined end to end, gaps <= 30 % bridged and reported, duplicates, nested loops = holes, several regions, LINE / ARC / CIRCLE / ELLIPSE / SPLINE / POLYLINE, a boundary inside a block, any layer case). If the layer holds anything, NEVER fall back to a wall polygon (without the layer: the biggest closed `82_KIR_OLE` polyline). Several regions: one round per region on a working copy (each gets the Xlines that cross it), dims accumulate, original entities restored; a region crossed by no Xline gives no dims - report it. On DIM.dxf the boundary follows the outermost wall line, ~60 outside the wall polygon `4AD` my first chains were clipped to (chains stopped ~60 short); chains are now clipped to the boundary itself, `plan_round` prints the 'CHAIN ENDS vs boundary' gap table every run, and whether the extra ~60 wall item at each end is wanted was never answered (the round was approved).
2. **Arcs**: flatten the outline through its bulges (`ezdxf.path.make_path(e).flattening(0.4)`; `get_points('xy')` ignores bulges: chains stopped 440-500 short of a curved wall).
3. **Chain ends = the outer face**: `plan_rows.line_faces` merges faces within 12.5 and keeps the inner one; `plan_xlines_lf.install` snaps the first / last face to the outline crossing.
4. **Tilted Xline -> aligned chain**: rotated linear dim, angle = Xline angle, items = crossings with every edge + edges PERPENDICULAR to it (|cos| < 0.045) within reach on the side with more of them; near-vertical tilted -> aligned with direction normalised upward (text upright). A horizontal chain 'beside' a tilted Xline is wrong.
5. **Clouds**: orange = add those elements' faces to the NEAREST chain (extension lines of any length; small elements fully inside -> min-x / max-x vertices; partly inside -> the vertices inside; no new line); red (missing sizes) = `plan_clouds.py` adds the faces INTO the chain (X size missing -> nearest horizontal chain, Y -> nearest vertical, reach <= 600 else reported); 'missing' is tested by extension points on THIS element (a same-length dim elsewhere is no coverage); blue-152 = extend to the outline; green-116 = align with the Xline. Two interleaved pier columns on one chain read as pieces (200 = 160.8 + 39.2): report it, do not fix it with extra lines. Xlines that miss the outline are skipped / deleted and REPORTED.
6. **Blocks = groups of elements**: an INSERT with no attribs, >= 5 entities, plain geometry on structural layers is read through its elements (`scripts/block_reader.py FILE [--box]` first; state what each block is). `plan_round` explodes them in the WORKING COPY only (8_KIR polylines narrower than 5000 are read as walls), runs the pipeline, removes the copies and restores the INSERT.
7. **Text placement** (`plan_repair.py`, style-aware via the dim style's real `dimtxt`): text centre from the line **dim_50 10.7** (his own hand position; 7 split the dim line in ezdxf - 771 of 1545 dims - and is superseded), **dim_100 18**; plan_repair also normalises the generator's 18 to the style's value; collisions moved to the nearest free place (other texts, other dims' extension / dimension lines, drawing TEXT, wall hatch; rotated dims supported). After ANY text move check `dimension line must stay ONE LINE in the block` (0 split). A cloud on one text is a rule for every text at the standard offset; after a text request he fine-tunes by hand: diff his save vs my output and adopt HIS number. Restrict bulk text / style passes to the boundary box (other plan copies carry the same tag).
8. **Wall items**: the text of a wall item (<= 150) moves slightly aside, along the line ~ item/2 + text half width + 12 (~35 for a 30 wall) toward the neighbouring span, perpendicular ~26 vs 18 (dim_100); span items and beam items are not moved.
9. **Re-run / restyle / rebuild**: a re-run keeps earlier dims by default; first delete only MY tagged dims near the boundary (xdata `CLAUDE_ROWS` / `xline_dims` - the generic tag may also sit on his own dims, other plan copies carry it too). New sample layer / style after a finished round (Xlines already gone): `plan_restyle.py FILE OUT` (my tagged dims only, texts kept; `set_location` before `render`), then `plan_repair.py`, snapshot, write - NOT a re-run. New rules on a finished round: `plan_rebuild_xlines.py` (recreates Xlines from my tagged dims) -> `plan_round.py` on a COPY -> checks -> write. Example: the 1 m reach fix 602 -> 485 dims, 0 far.
10. **Approval**: when he says 'good job', delete any remaining Xlines on `claude_DIM` / `claude` (they run past the outline), keep dims and the clouds he left, snapshot first. He saves between every turn (removes clouds, may add a dim): re-read the file and build on HIS save, never restore an older snapshot over it.
11. **After a round**: `plan_reach_audit.py` (far = 0 of mine), a split-line check, `plan_repair` collisions = 0, `dxf_inspect.py audit`, zoomed renders; report what you could not place (unplaced dim, unknown cloud colour).

## 3. Mode B - automatic slab / floor plan (`plan_rows.py`; the user's example lines of 2026-10-13, 'gallery -1')
Beyond sections 1-2: perimeter wall to perimeter wall (his X line y=40495 had 29 items, 10166 wide; Y line x=80550 16 items, 5809), exact integer-program choice of the FEWEST lines (`plan_rows.ilp_cover`, scipy `milp`, greedy fallback; constraints: one side, reach, parallel lines >= 60 apart, a line never within 3 of a parallel edge, never through his texts; overall items of tooth beams / stairs are REQUIREMENTS of the cover; ties = shortest extension lines).
- **Not dimensioned**: `6_HATCH`; the 15-wide BEARING TEETH of plank (Luchad) beams (thin `15_DASHED` U-strips; the beam gets its OVERALL width, the two `93_KORA` faces, as ONE item - `plan_rows.is_tooth`); interior step lines of a STAIR.
- **Stairs**: a blue ACI-177 cloud marks a stair on `15_DASHED`; ONE overall extent per direction = bounding box of the `15_DASHED` geometry inside the cloud (east 335 x 233, west 125 x 54), each guaranteed as one item.
- **Openings**: an X mark on a wall (INSERT on `82_KIR_OLE`, 4-vertex bowtie, 200 x 30 / 20, may be rotated 3.8 deg) = an OPENING: its two end faces are elements (kept even when < 20) so the width becomes an item of the existing line; apply to EVERY instance in the plan (the gallery has ten, he clouded three). Door jambs (20-25) count as faces.
- **Texts**: `place_texts` locates every text explicitly (ezdxf honours `location` exactly; its default sits 23 out for narrow items) by cost: along the line 0, +-12 ...; perpendicular = style side then the other side then 44 / 70; audit `plan_overlaps.py` = 0 (X / Y dims only - it treats every non-0 angle as Y; use plan_repair for rotated dims).
- **Run / re-run**: `plan_rows.py FILE --box X0 Y0 X1 Y1 --replace --expect MTIME` (own output tagged `CLAUDE_ROWS`; the box must include the perimeter wall and ONE plan copy - list every `9_KONTUR` contour > 5000 wide first and audit each; snapshot taken; `dxflib.backup` keeps only 6 snapshots per tag). Then `plan_crossings.py --tol 12.5` (continuity, side, uncovered crossings, text shifts - run it on his example lines to relearn the rules), `plan_overlaps.py`, `dxf_inspect.py audit`, tests.
- **Field-engineer size pass** (`plan_sizes.py`): every wall / pier / beam pair gets its own width and length as a face-to-face X / Y item when no line has it; idempotent (second run adds 0).
- UNVERIFIED: whether outer-wall faces, hidden `15_DASHED` lines and the remaining stair-mark neighbours should stay dimensioned (his example omits some crossings: audit the example too, ask once); opening depth (wall thickness) per opening; whether overall extents / grid references are wanted.

## 7. Legacy site-plan facts (ramla_base, first generation; superseded by sections 1-4 wherever they differ)
- Pier-row chains: ONE continuous chain replaces the per-pier dims (every pier / crossed wall width + clear span, no overall dim), dim line 101 beyond the piers' edge, `dim_100`, text above; picks up shaft / stair walls (25, 20) and the 150 x 40 piers within +260; Y example: items 35 | span | 200 | span ... also double-line walls (30, 35) and the outline strip; start / end faces = innermost outline face (+ outer face if 15..45 further out). `plan_chains.py` reproduces both user examples.
- Shaft / pit blocks: the user's example chains (3 vertical face chains, items between the vertices of each wall line, ~92 off the west face) + overall height, the same on every block; openings between wall pieces are items of the existing chain (y=27185: 25|240|25|140|25|240|25). Skewed tanks: ONE vertical chain wall | clear | wall. Thin hidden rectangles (<= 50): length only. Single pier outside a row: length + thickness next to it, not crossing a chain.
- Office finished example (`דומגא לתוכנית מידות.dxf`): continuous chains along grid cuts, one overall per side, a chain of main parts ~29 inside it, detail chains; extension points snap to wall faces (470 of 806 on `82_KIR_OLE`).
- Superseded generators: `plan_lines.py` (full-width greedy lines), `plan_gallery.py`, `plan_tidy.py` (its rules G2 / G3 deleted what the user wants), `plan_review.py`, `plan_revise.py`; `plan_lines`' rule 'dimension also outside the slab contour' survives as principle 11.
