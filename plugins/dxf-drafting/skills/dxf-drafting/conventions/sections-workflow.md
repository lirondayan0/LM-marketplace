## 2. Marks, orientation, numbering
- **Marks**: S = reinforcement as per plan; SS = the engineer chooses (`X$XX`); ST = S with TRANSFER stirrups; stirrup table by MARK (S / SS standard, ST transfer; `transfer_check.py` informational only; supersedes every earlier 'transfer' result). Pairs with different marks never share a section.
- **Pairing**: the FILE-ADJACENT INSERTs (a pair is drawn / copied as a unit; nearest-neighbour mis-paired 245 vs 288 apart), pair length 100..500 (a 380-apart ST pair was once lost at 320), tilted pairs accepted within 6 deg (view snapped to 90 deg), `--max-y 1e9` (the old 40000 default silently hid a plan at y=177000). Every pair must end up numbered: count `hat` inserts / 2 vs numbered pairs at the end of EVERY round.
- **Orientation** (`star_orient.py FILE --max-y 1e9 --tidy W`, snapshot first): pairs that look E/W (horizontal beams) are turned CLOCKWISE about the centroid of the marked pairs - north side looks E, south side W (slab on the RIGHT of the view for edge beams); pairs looking N/S (vertical beams) are turned too (user 2026-10-25, test_sections: east beams looked N = counter-clockwise): east side looks S, west side N - the slab of an edge beam is always on the RIGHT of the view. A turn = ROTATE THE WHOLE PAIR 180 deg as one rigid object: blocks AND number attributes (hat rot 270 -> 90, mirror signs swap, attribute local position stays the block default lx 16.5 (+) / 28.55 (-), ly 11.9), and the turned pair is CENTRED on the beam axis (mid of the two outline lines); never moved along the beam; moving an INSERT leaves its ATTRIBs behind (`place_numbers` re-places them). Reading of 'clockwise' ?.
- **Numbering**: sequential WITHOUT gaps, STARTING AT THE RIGHT and running CLOCKWISE round the plan from the centroid - east, then south (the bottom runs right to left), west, north (user 2026-10-24 'number the sections from right to left, clockwise'; `star_plan.clock_key`; UNVERIFIED reading of 'start': east of the centroid; the previous rule started at north); identical beams (same recipe + args) share one section and number, the cell carries `זהה ל-N קורות` under the scale text; two-digit titles digit-reversed; the mark text (S/SS/ST) is REPLACED by the section number. `star_plan --draw` renumbers the marks even if a recipe subprocess failed: after any traceback check the titles exist.

## 3. Layout of the sheet (STANDING, user 2026-10-16/21/22)

2. **Titles of a row share ONE line** (`fit_rows.py`, run by sections_round; cells read from the dividers): short sections stay at the top, tall beams hang from it; never centre vertically one by one. ## 4. THE ROUND - one command, then the finishing checklist
`python recipes/sections_round.py FILE [--dry] [--side ..] [--first N] [--png OUT]` runs, in order: (1) `star_orient --max-y 1e9 --tidy W`; (2) `star_plan --kontur` (read-only; a pair NOT DRAWN is a hard WARNING - read that cut yourself with `cut_faces`, tag layers `451TEXT_KORA_100` / `45_TEXT_KORA`); (3) free space; (4) `star_plan --draw --cells-at` (rows of 10, titles centred, marks renumbered; generators `ledge_beam` / `general_beam` / `slab_edge`); (5) finish passes: `sivan_text` (Hebrew notes SIVAN, `$` notes HEBREW_NEW) -> `leader_fit` -> `rebar_color` (layer colours) -> `mid_note_fit` -> `ok_marker --once` -> `align_row` -> `cell_dupes --fix` -> `text_overlap --fix` -> `bar_arrays` (LAST write, AutoCAD accoreconsole; if absent say so - dots stay loose); (6) verify: reload + audit, COVERAGE (marks in the kontur vs numbered), PNG of the rows. Adding to an existing row: call `star_plan --kontur --draw --first N` directly (sections_round would restart at 1 and open a new row), then run the finish passes on that cell.
**Checklist after the run (do not skip; details in sections-drawing.md)**
1. Every pair numbered (COVERAGE line); no recipe WARNING left unread (stirrup row beyond the table, section wider than its cell, pairs not drawn).
2. Per section: stirrup n and w against `stirrup_layout` in the section AND the detail row; middle-steel note vs area; largest vertical bar-row gap <= 1.5 x spacing; side dimension chains; every solid-slab bar 60 into the beam (top bar through only where the slab tops are flush); no restraint mesh; solid slab default + symbol `H` where the plan gives no thickness; levels per side read from S_M markers (list UNVERIFIED sides).
3. Text: SIVAN notes, `$` notes HEBREW_NEW (0 HEBTXT `$` notes left), no overlapping text (`text_overlap.py` 0 pairs; stacked bottom notes staggered), middle-steel note clear, leaders: forks on dot centres, shelves = text width.
4. Doubled bars: `cell_dupes.py` 0; after any `--replace` count the dots in the render (`clear_cell` must know every entity type a recipe draws).
5. Colours: rebar layer 4, leaders 6, dims 2 (layer table); arrays hold the layer colour BYLAYER inside the block - check after `bar_arrays`.
6. Layout: margins L/R/T/B of every frame, 100 gaps, one title line per row, nothing beyond the frame.
7. Sloped slabs (label only) and roller-shutter texts are found and drawn by the round itself (`star_plan` markers `--slope` / `--rshutter`, free edge `slab_edge --shutter`, under a general beam `beam_shutter`); read the planner notes for 'SLOPED SLAB' / 'ROLLER SHUTTER' and the UNVERIFIED flags.
8. Render each section zoomed (geometry clear, dims readable, no text over bars) and READ one Hebrew note; `dxf_inspect audit` 0 errors; re-run the idempotent steps (a second run must change nothing).
9. **Visibility gate (netivot 2026-10-24 - the user saw no titles, rebar or dimensions)**: the plan's layers may arrive FROZEN (54 text, 57 bars, 53 dims ...). section_visibility.py FILE --box ... (run by sections_round before the arrays and again read-only at the end, and by the app) must say problems: 0: every layer the sections use ON / thawed / unlocked, every array on 57_HATAH_ZIUN, a visible title. Thawing is global: tell the user which layers it thawed (the plan's own notes on them appear). A render that shows no titles / rebar is a FAILED round, never a finished one. Judge the result with the layer states the user will see (render honours freezes).

Report: per section beam / slab / stirrups as printed by the planner, pairs not drawn and why, UNVERIFIED items (D template, H=40 for untagged beams, stirrup row beyond the table, slab sides copied, beam level assumed), whether bar_arrays ran. ## 8. Array arrows and notes on wide beams (user 2026-10-25, netivot 9-9)
